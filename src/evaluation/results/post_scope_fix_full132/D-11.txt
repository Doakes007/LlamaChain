QUESTION:
Using Figure 3, explain how Donut converts a document image into a structured JSON-like output.

GROUND TRUTH ANSWER:
Figure 3 shows the image first entering Donut's Transformer visual encoder, which converts it into embeddings. The textual decoder uses those embeddings to generate a sequence of tokens. That output sequence is then converted into the target structured representation, such as JSON; the figure illustrates this with a receipt/question example.

2.2 Document Understanding Transformer

Donut is an end-to-end (i.e¢., self-contained) VDU model for general understand-
ing of document images. The architecture of Donut is quite simple, which con-
sists of a Transformer [58,9]-based visual encoder and textual decoder modules.
Note that Donut does not rely on any modules related to OCR functionality
but uses a visual encoder for extracting features from a given document im-
age. The following textual decoder maps the derived features into a sequence
of subword tokens to construct a desired structured format (e.g., JSON). Each
model component is Transformer-based, and thus the model is trained easily in
an end-to-end manner. The overall process of Donut is illustrated in Figure 3.

into a set of embeddings {z,|z,;ER¢, 1<i<n}, where n is feature map size or the

encoder. Note that CNN-based models [17] or Transformer-based models [9,40]
can be used as the encoder network. In this study, we use Swin Transformer [40]

parsing. Swin Transformer first splits the input image x into non-overlapping

self-attention module and a two-layer MLP, are applied to the patches. Then,
patch merging layers are applied to the patch tokens at each stage. The output

 Donut converts a document image into a structured JSON-like output through the following process:

1. Visual Encoder: The input document image is first converted into a set of embeddings by the visual encoder. This encoder can be based on CNN or Transformer models, and in this study, Swin Transformer is used due to its superior performance in document parsing. Swin Transformer splits the input image into non-overlapping patches, applies Swin Transformer blocks (consisting of a shifted window-based multi-head self-attention module and a two-layer MLP), and patch merging layers at each stage. The output of the final Swin Transformer block is a set of embeddings {z,|z,;ER¢, 1<i<n}, where n is the feature map size or the number of image patches and d is the dimension of the latent vectors of the encoder.

2. Textual Decoder: The output of the final Swin Transformer block {z} is fed into the textual decoder. The decoder maps the derived features into a sequence of subword tokens to construct a desired structured format (e.g., JSON). Each model component is Transformer-based.

3. Output Conversion: The output token sequence is converted to a desired structured format, such as JSON. Special tokens like [START ∗] and [END ∗] are added to the sequence to extract specific fields. If the output token sequence is wrongly structured, the field is treated as lost.

In summary, Donut directly maps an input document image into a desired structured output without relying on any modules related to OCR functionality. The output is in the form of a JSON-like structure.
