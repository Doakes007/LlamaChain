QUESTION:
How does information flow through Donut from the input document image to the final structured output?

GROUND TRUTH ANSWER:
The input document image is processed by the visual encoder (Swin Transformer), which produces visual embeddings. The textual decoder then conditions on those embeddings and generates a sequence of subword tokens. The token sequence is converted into a structured output such as JSON using the task-specific output format/parsing rules.

2.2 Document Understanding Transformer

Donut is an end-to-end (i.e¢., self-contained) VDU model for general understand-
ing of document images. The architecture of Donut is quite simple, which con-
sists of a Transformer [58,9]-based visual encoder and textual decoder modules.
Note that Donut does not rely on any modules related to OCR functionality
but uses a visual encoder for extracting features from a given document im-
age. The following textual decoder maps the derived features into a sequence
of subword tokens to construct a desired structured format (e.g., JSON). Each
model component is Transformer-based, and thus the model is trained easily in
an end-to-end manner. The overall process of Donut is illustrated in Figure 3.

Encoder. The visual encoder converts the input document image xeR#*W*¢

into a set of embeddings {z,|z,;ER¢, 1<i<n}, where n is feature map size or the
number of image patches and d is the dimension of the latent vectors of the
encoder. Note that CNN-based models [17] or Transformer-based models [9,40]
can be used as the encoder network. In this study, we use Swin Transformer [40]
because it shows the best performance in our preliminary study in document
parsing. Swin Transformer first splits the input image x into non-overlapping
patches. Swin Transformer blocks, consist of a shifted window-based multi-head
self-attention module and a two-layer MLP, are applied to the patches. Then,
patch merging layers are applied to the patch tokens at each stage. The output
of the final Swin Transformer block {z} is fed into the following textual decoder.

 Information flows through Donut as follows:

1. The input document image is processed by the visual encoder, which converts it into a set of embeddings. In this study, Swin Transformer is used as the encoder network.

2. The encoded embeddings are then fed into the textual decoder, which maps the derived features into a sequence of subword tokens.

3. The sequence of subword tokens is used to construct a desired structured format, such as JSON. Each model component is Transformer-based, and thus the model is trained easily in an end-to-end manner.

4. The final structured output is the answer to the question posed, in the form of the desired structured format (e.g., JSON).

In the example provided, the input image and prompt were a receipt for choco mochi, and the question was "what is the price of choco mochi?". The model generated the answer "14,000" in the form of a JSON object.

Donut does not rely on any modules related to OCR functionality, but it uses a visual encoder for extracting features from a given document image. This makes it an end-to-end (self-contained) VDU model for general understanding of document images.
